# 동작 정의와 디렉팅 해석

사용자는 "터프하게", "어색하다", "발레 같다", "스프링 인형 같다", "AI 같다"처럼 **정량적이지 않은 말**로 디렉팅한다.
이 문서는 (1) 그런 말을 애니메이션 원칙으로 번역하는 절차와 (2) 지금까지 정의한 동작 사전을 담는다.
정의가 쌓일수록 다음 해석이 빨라진다 — 새 정의는 사용자 확인을 받고 아래 사전에 추가한다.

## 1. 디렉팅 해석 절차

모호한 요구를 받으면 곧바로 생성하지 않는다. 지시자·수행자·검증자가 모두 LLM이면 같은 착각이 걸러지지 않는다(2026-10-15 사용자 지적).
외부 기준(애니메이션 이론·연구·사람이 만든 레퍼런스)으로 요구를 고정한 뒤 움직인다.

1. **사전 확인** — 아래 3절에 같은 말이 있으면 그 정의를 쓰고 2로 건너뛴다.
2. **조사** — WebSearch로 그 말이 애니메이션에서 무엇을 뜻하는지 찾는다. 같은 턴에 여러 갈래로 동시에:
   - 애니메이션 원칙: 예비 동작, 스미어, 팔로스루, 이징(fast-out / slow-in), 과장, 2차 동작, 무게감
   - 게임 공격 구조: 발생(startup)·판정(active)·경직(recovery), 히트스톱
   - 실제 신체 역학: 그 동작을 하는 사람의 힘 전달 순서(예: 펜싱 런지 = 뒷다리 → 엉덩이 → 몸통 → 팔)
   - 사람이 만든 레퍼런스(무료 우선, 4절)
   출처가 블로그·요약 사이트면 숫자는 "경험칙"으로만 쓴다.
3. **정의 작성** — 조사 결과를 이 프로젝트의 **측정 가능한 정의**로 바꾼다. 형식:
   - 구간: 각 단계와 원본 프레임 수, 보간 장수(`--gap_counts`), 멈춤 유무
   - 포즈: 단계별 몸의 상태(무게 중심, 어느 다리가 힘을 쓰는지, 과장 정도)
   - 금지: 그 말과 반대되는 것(예: 터프함 → 중간 정지, 고른 속도)
   - 검사: 결과에서 무엇을 재면 정의를 지켰는지 알 수 있는지(5절)
4. **사용자 확인** — 정의를 짧게 보여 주고 출처를 단다. 사용자가 고치면 반영한다.
5. **비교로 확인** — 결과는 하나만 보여 주지 않는다. `AnimationCompareRecorder`로 이전 것과 나란히 녹화해 고르게 한다.
   "어색하다"처럼 원인을 못 짚는 피드백이면 원인 후보마다 한 버전씩 만들어 비교한다(예: 보간 / 보간 없음 / 완급).
6. **사전에 기록** — 확정된 정의를 3절에 추가한다.

### 말 → 원인 후보 (지금까지 실제로 나온 것)

| 사용자 표현 | 측정해 보니 원인 | 해결 |
|---|---|---|
| "부들거린다", "지터링" | 발 검출 오류(망토 끝을 발로), 상체 위치가 프레임마다 튐, 보간 셀만 흐림 | 발 검출, `--stabilize`, 선명도 맞춤 |
| "AI가 만든 듯 불쾌하다" | 프레임마다 얼굴·세부를 새로 그림, 부위가 따로 움직임 | Idle은 반자동(`procedural_idle.py`) |
| "스프링 인형 같다" | 상체가 통째로 오르내리며 다리를 누름 | 다리 고정 + 가슴 호흡, 무릎 굽힘은 앞으로 |
| "발레 같다", "너무 스무드" | 전 구간 고른 보간, 균일 속도 | 구간별 보간 장수, 발사 구간 보간 없음 |
| "중간에 멈추는 건 터프하지 않다" | 멈춤(hold)으로 무게감을 표현 | 멈춤 대신 긴 팔로스루 |
| "앞뒤로 왔다 갔다" | 모델이 "더 밀어붙여라"를 재찌르기로 그림 + 움직이는 발을 정렬 기준으로 씀 | 그 원본 프레임 제외, 바닥에 박힌 발로 정렬 |
| "짜리몽땅", "얼굴이 크다" | 다리 갈라짐·허리 높이, 머리카락 부피·드러난 이마 | 측정으로 원인 규명 후 해당 부분만 편집 |
| "좌우로 흔들린다" | 바닥까지 내려온 칼날을 발로 잡음(고침: `FOOT_FILL`) + 원본 장마다 보폭을 다르게 그림(정렬로 못 고침) | 생성 규칙에 "뒷발은 모든 프레임 같은 자리" 명시, 뒷발 정렬 |
| "뜬금없이 푹 쓰러진다" | 피격 반동·비틀거림 없이 선 자세에서 바로 기울어짐, 무릎을 편 채 통나무처럼 넘어감 | 데미지 사망 정의(3절 초안) |
| "애니메이션별로 크기가 제각각" | 키·턱~발바닥은 맞는데 AI가 시트마다 머리·몸통 부피를 달리 그림(Knight 준비 자세가 Idle보다 +2~6%) | 파이프라인 `size_fit`: 기준 프레임을 기준 시트 0번 실루엣에 IoU로 맞춤 → ±2% |
| "A랑 B 크기가 다르다"(같은 동작 안에서) | 여러 장으로 나눠 생성하면 장마다 인물 크기가 다름(Knight Hit 둘째 장 머리 +15~20%) | 파이프라인 `equalize_parts`: 장별 얼굴 크기 중앙값을 첫 장에 맞춤(3~15%만, 얼굴이 안 보이는 장은 건너뜀) |
| "칼이 순간이동한다" | 포즈마다 칼 위치를 모델이 자유롭게 그림(던지듯 뻗기, 치켜들기) | 생성 규칙에 "칼은 모든 프레임 오른손, 칼끝 아래, 앞 프레임에서 조금만" 명시. 칼날 측정은 흰 갑옷과 섞여 못 쓴다 — 눈으로 확인 |
| "Hit가 어색하다" | 생성 지시가 "부끄러워하는(blush) 반응"이었다 — 아픔이 아님 | 아파하는 피격 정의(3절) |
| "뚝뚝 끊긴다" | 한 구간만 자세 변화가 큼(점프), 번짐으로 끊은 구간 | `smoothness.py`로 찾아 그 구간만 처리 |

## 2. 조사 출처 (2026-10-15)

- 애니메이션: [Pixelblog 9 — Melee Attacks](https://slynyrd.com/blog/2018/9/8/pixelblog-9-melee-attacks), [Pixelblog 56 — Top Down Attack](https://www.slynyrd.com/blog/2025/5/23/pixelblog-56-top-down-character-attack-animation), [GDQuest — Juicy attack](https://www.gdquest.com/library/juicy_attack), [animation-principles: game development](https://playbooks.com/skills/dylantarre/animation-principles/game-development)
- 격투게임 프레임: [Dustloop — Using Frame Data](https://dustloop.com/w/Using_Frame_Data), [Capcom SF Seminar](https://game.capcom.com/cfn/sfv/column/131432?lang=en)
- 펜싱 런지 역학: [Biomechanical determinants of lunge speed](https://sponet.de/Record/4049794), [Kinematic chain in the attacking lunge](https://ojs.ub.uni-konstanz.de/cpa/article/view/6606)

요점: 공격 = 예비 → 스미어(1장, 짧게) → 팔로스루(무게는 여기서) → 회복. 시작은 fast-out, 회복은 slow-in.
예비 동작이 길면 굼떠 보인다. 포즈는 현실보다 20~30% 과장. 히트스톱(2~5프레임)은 게임 로직이 맞았을 때 거는 것 — 애니메이션에 넣지 않는다.

## 3. 동작 사전 (사용자 확정)

### 스피디하고 터프한 찌르기 (Knight Skill1, 2026-10-15 "그나마 제일 좋다")
- 원본 12장 생성 → 재찌르기·재전진 프레임 2장 제외 → 9장 + 구간별 보간 = 18장, 30fps, 0.6초
- 구간: 준비 → 예비(보간 1) → 웅크림(1) → **발사: 보간 0, 칼날 스미어 1장** → 임팩트(0) → 팔로스루(1) → 회복(2, 2, 2)
  `--gap_counts 1 1 0 0 1 2 2 2`
- 포즈: 뒷다리가 폭발적으로 펴지며 몸 전체가 낮게 날아감, 임팩트에서 팔·칼이 어깨에서 일직선, 머리카락·망토가 뒤로 휨. 25% 과장.
- 금지: 중간 멈춤(hold), 고른 보간, 최대 뻗음 이후 다시 앞으로 가는 프레임, 앞발로 정렬
- 정렬: `left_foot`(뒷발이 바닥에 박혀 있음)
- 레퍼런스: Crimson Samurai(CC0) 찌르기 프레임 — `SpriteRegen/_refs/stab_ref_sheet.png`

### 터프하고 간결한 내려 베기 (Knight Skill2 v4, 2026-10-15 사용자 선택)
- 사용자: "좀 더 터프하고 간결하게, 궤적은 크게" + "좌우로 흔들리면 안 된다"
- 원본 8포즈(`knight_skill2_tough.json`) + `--gap_counts 1 0 0 1 2 2 1` = 15장, 30fps, 0.5초
- 구간: 준비 → 한 번에 머리 위로 올리기(보간 1) → **내려 베기: 보간 0, 몸보다 큰 반달 궤적** → 임팩트(궤적 꼬리, 0) → 버팀(1) → 복귀(2, 2, 1)
- 금지: 긴 예비 동작, 임팩트 뒤 칼이 다시 뒤로 가는 것, 장마다 보폭이 다른 것
- 정렬: `left_foot`. 생성 규칙에 "뒷발은 모든 프레임 같은 자리, 앞발만 한 번 내딛음"을 넣어야 한다 — 없으면 장마다 보폭이 달라 어떤 정렬로도 좌우 흔들림이 남는다(174px)

### 데미지 사망 (Knight Dead v3, 2026-10-15 사용자 선택: 앞으로 무릎 붕괴)
- 사용자: "너무 뜬금없이 푹 쓰러진다" → 맞아서 쓰러지는 인과가 보여야 한다.
- 원본 12포즈(`knight_dead_knee.json`) + `--gap_counts 0 1 1 1 1 1 1 0 0 1 2 --hold 11:0.4` = 21장, 24fps, 약 1.3초, anchor 정렬
- 남은 흠: 장 경계(포즈 8→9)에서 누운 몸 위치가 한 번 옮겨진다.
- 구간(12포즈): 피격 반동 2(상체가 공격 반대쪽으로 튕김) → 비틀거림 2(버티려다 무너짐, 손이 상처로) → 무릎 꺾임 2~3(골반이 먼저 수직으로 떨어지고 상체는 서 있음) → 낙하 2(가장 빠름) → 착지·작은 튐 1~2(칼이 튕겨 나감) → 정착 1(길게). 빠르게 시작해 느리게 끝, 총 0.9~1.2초.
- 금지: 반동 없이 바로 기울기, 무릎 편 채 통나무처럼 넘어가기, 골반 높이가 그대로인 채 상체만 회전, 모든 간격이 같음.
- 변형: 앞으로 무릎 붕괴(`knight_dead_knee.json`, 채택) / 뒤로 주저앉음(`knight_dead_back.json`, 비교 후 탈락).
- 출처: [TV Tropes — Knee Fold Fall](https://tvtropes.org/pmwiki/pmwiki.php/Main/KneeFoldFallOfDefeat), [VF wiki — crumple](https://virtuafighter.com/wiki/hit-effects/), [ChiliGames Knight R0(CC0)](https://opengameart.org/content/knight-and-knight-animation), Muybridge Plate 272(퍼블릭 도메인, 무릎부터 무너지는 순서 관찰). 자유 라이선스의 "피격→비틀→낙하" 한 벌짜리 칼잡이 시트는 못 찾았다. ChiliGames R0는 2등신 투구라 실루엣으로 바꾸면 자세가 안 읽혀 레퍼런스로 붙이지 않았다.

### 아파하는 피격 (Knight Hit v4, 2026-10-15 — 사용자가 B 방향 선택, 칼·크기 규칙 추가 후 최종)
- 사용자: "맞고 아파하는 여성 스프라이트가 뭔지 학습이 필요"
- 구간(8포즈): 충격 1(머리가 뒤로 젖혀짐, 눈 질끈·입 벌림, 머리카락·망토는 아직 제자리) → 반동 2(몸이 뒤로 밀리고 무릎이 굽어 키가 줄어듦, 머리카락·망토가 맞은 방향으로 늦게 휨) → 고통 3(웅크림, 빈손을 상처에, 검끝 처짐 — 가장 김) → 회복 2(고개부터 듦). 0.45~0.6초
- 금지: 무표정이나 엉뚱한 감정(blush), 충격 프레임 없이 서서히 기울기, 고통 구간 없이 바로 복귀, 머리카락·망토가 몸과 같은 프레임에 움직임, 발 미끄러짐
- 검사: 머리 x가 충격 직후 가장 왼쪽 → 끝에서 0, 반동·고통 구간 키 5~10% 낮음
- spec: `knight_hit_pain2.json`(B 방향 + 칼 고정·발 고정·크기 규칙). `--gap_counts 0 1 1 2 2 2 2` = 18장, 30fps, 0.6초, both_feet. 레퍼런스: 쓸 만한 무료 여성 피격 시트가 작은 픽셀 아트뿐(Clembod Warrior는 재배포 금지, LuizMelo Huntress 2는 CC0지만 3프레임·판독 불가)이라 붙이지 않았다
- 출처: [game-development animation principles](https://playbooks.com/skills/dylantarre/animation-principles/game-development), [KOF 히트스턴](https://dreamcancel.com/?p=2146), [UFE 포럼 — 흔한 실수](https://ufe3d.com/forum/viewtopic.php?id=3754), [Animation Mentor — 2차 동작](https://www.animationmentor.com/?p=94905), [Guilty Gear Xrd GDC](https://www.ggxrd.com/Motomura_Junya_GuiltyGearXrd.pdf)

### 의장대식 칼 돌리기 (Knight Skill3, 2026-10-15 초안 — 사용자: "군대 예장대처럼 절도있게 휘릭 몸 앞에서")
- 실패한 해석: 몸을 감싸는 큰 원형 궤적(어깨로 휘두름) — "둘 다 별로"
- 정의: 받들어 칼(날밑이 턱 앞) 정지 → **손목만으로 몸 앞 수직면에서 1바퀴**(12→3→6→9→12, 손은 가슴 앞 한 점, 팔꿈치·어깨·몸 정지) → 시작 각도에서 **파워 스톱**(흔들림 없이 딱) → 칼끝 내려 꽂기
- 절도 = 급정지 + 키 포즈 홀드 + 회전 중 몸 완전 정지 + 잔상은 칼날에만. 엉성함 = 이즈아웃, 큰 원호, 몸이 따라 흔들림
- 회전 면: 사용자 선택 "몸 앞 수직면(실제 의장대)" — 3/4 시점에선 원근으로 칼날 길이가 변하며 돈다
- 1차(생성 회전 4장 끼우기): 사용자 "칼 회전만 더 부드럽게, 회전 중 칼 크기 변하지 않게, 몸 젖히지 말고 선 채로"
- 2차(절차 회전): 경례 장에서 칼을 떼고, 칼을 지운 몸은 Codex에 "같은 그림에서 칼만 지워라"로 받아(IoU 0.98로 정렬) 그 위에 같은 칼 그림을 주먹 중심으로 돌려 얹는다 → 몸 완전 고정, 칼 크기 일정, 각도를 원하는 만큼 잘게(15·45·80…325°, 30fps, 0.33초), 칼날에만 잔상 3겹, 장갑은 칼 위에 다시 덮는다. 손으로 메운 몸(확산 채우기)은 뺨·머리카락에 네모난 얼룩이 남아 못 썼다
- 2차 지적: "원래 몸이 살짝 뒤로 젖혀져 있다, 회전하는 칼이 장난감 같다(평면 그림을 통째로 돌림 — 광택까지 같이 돈다), 손이 부자연스럽다(손은 멈추고 칼만 돈다)"
- 3차(손목 회전 생성): 칼 없는 몸을 "똑바로 선 자세"로 다시 받고, 그 몸 + 칼 그림을 붙여 45°마다 손목·주먹이 칼을 돌리는 8장(2x2 두 장)을 생성, 그대로 잇는다(손·칼만 떼어 얹는 합성은 장마다 정렬이 어긋나 이중으로 보였다). 회전 앞뒤 경례도 생성된 0° 장을 쓴다
- 크기 맞춤: 칼이 얼굴을 가리면 얼굴 크기 측정이 틀린다 → 선 자세끼리는 칼날을 깎은(MinFilter 9) 실루엣 키로 맞춘다
- 4차: "여전히 앞을 보는 것 같다" — 맞았다. "똑바로 선 몸"을 다시 그릴 때 몸이 정면으로 돌았고 그 몸을 기준으로 그린 8장이 전부 따라갔다. 장끼리만 비교해서 놓쳤다 → 시점 확인은 **반드시 Idle 0번과 나란히**. 다시 생성할 때는 몸 기준을 Idle(generate_action의 character.png)로 두고 "3/4 view facing right, never toward the camera"를 규칙에 넣었다(`knight_skill3_wrist.json`)
- 5차(최종 v6, 사용자 A안 선택): "새 프레임이 기존 프레임과 크기가 안 맞는다" — 칼날 뺀 키로만 맞췄더니 몸통·망토가 가는 새 그림이 작아 보였다(첫 장 −5%). 칼이 세로인 장면만 골라 칼날을 깎은 실루엣을 기존 준비·칼끝 내리기 장면에 IoU로 맞춰 배율을 정했다(1.055 / 0.975). 키 하나보다 실루엣 전체가 보이는 크기에 가깝다
- 보간 금지: RIFE는 도는 가는 칼날을 못 따라가 중간 그림에서 칼이 사라진다 — 회전 구간 gap 0
- 출처: [미 육군 사브르 교범](https://www.drillpad.net/DPsword_Army.htm), [드릴 용어 — Front spin / Power stop](https://thedrillmaster.org/2012/05/31/drill-move-levels-and-move-definitions/), [moulinet](https://www.tota.world/article/2154), 미 국방부 공공저작물 사진(`SpriteRegen/_refs/twirl_candidates/SOURCES.txt`)

## 5. 정의를 지켰는지 재는 법

| 정의 | 측정 |
|---|---|
| 한 번 찌르고 돌아온다 | 최대 뻗음 이후 칼끝 x·몸통 x가 3px 넘게 다시 앞으로 가는 구간 0개 (`motion_check.py once`) |
| 끊김 없음 | `smoothness.py` 점프 2.5배 이하, 정지 0 (발사 구간 점프는 의도) |
| 비율 유지 | 크기 기준 시트와 나란히 놓고 눈으로. `sheet_check.py proportions`는 참고만(은분홍 머리카락을 피부로 잡고, 발을 들면 신발을 못 잰다) |
| 칼끝 안 잘림 | 분할 경고 없음, 미리보기 확인 |
| 같은 크기 | 장마다 캔버스 크기가 같은지 (다르면 그 세트는 버린다) |

지표가 "합격"이어도 사용자 판단이 우선이다. 지표는 원인을 좁히는 데 쓴다 — Idle 몸 일관성 지표와 비율 지표 모두 합격인데 사용자는 어색하다고 했고, 사용자가 맞았다.
