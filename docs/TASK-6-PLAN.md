# 작업 [6] 계획서 — 2단 추첨과 사망 재정규화

## 1. 목표

`PuzzleFactory`의 현재 전체 후보 균등 추첨을 GDD §3.2의 2단계 가중 추첨으로 교체한다.
플레이어 캐릭터가 사망하면 GDD §3.2.1의 계층을 따라 생존 캐릭터 기준으로 스포닝 지분을 재정규화한다.

완료 후 보장해야 하는 결과는 다음과 같다.

- 아군 3인 생존 시 캐릭터별 `30% / 30% / 30%`, 공용 특수 버블 `10%`
- 아군 1인 사망 시 생존 캐릭터별 `45% / 45%`, 공용 특수 버블 `10%`
- 선택된 캐릭터 안에서는 세 스킬의 `BubbleSO.spawnWeight` 비율로 최종 버블 선택
- 사망 캐릭터의 버블은 이후 새로 생성되지 않음
- 사망 전에 현재 조작용으로 확정된 리필 결과는 변경하지 않음
- 보드에 이미 남아 있는 사망 캐릭터 버블은 그대로 유지

## 2. 근거와 제약

- 기획의 단일 원천: `docs/GDD.md` §3.2, §3.2.1
- 구현 순서의 근거: `docs/HANDOFF.md` §4 작업 `[6]`
- 계층 규칙: `docs/AGENT.md` §1, §5
- 영수증 불변 규칙: `docs/AGENT.md` §3
- `PuzzleManager`는 `Actor`를 직접 참조하지 않는다.
- 하위 매니저인 `BattleManager`와 `PuzzleManager`는 직접 통신하지 않고 `GameManager`를 거친다.
- `docs/GDD.md`, `docs/GDD-TODO.md`, `docs/AGENT.md`는 이번 작업에서 수정하지 않는다.
- 이 저장소에는 Unity 참조 어셈블리가 없으므로 에이전트가 컴파일을 검증할 수 없다. 코드 변경 후 Unity 에디터 확인이 필요하다.

## 3. 현재 상태

### `PuzzleFactory`

- `InjectBubbleSpecs(List<BubbleSO>)`로 평면 후보 목록을 받는다.
- `PackBubble`은 전체 후보에서 `Random.Range`로 균등 추첨한다.
- 캐릭터 소유 관계와 `spawnWeight`를 알지 못한다.

### `PuzzleManager`

- `skillOwners`에 `BubbleSO → CharacterSO` 매핑을 보유한다.
- `BuildSpawnTable()`이 캐릭터 스킬과 공용 버블을 평면 목록으로 합친다.
- 새 버블이 필요할 때 `PuzzleFactory.PackBubble()`을 호출한다.
- 아직 캐릭터 사망 신호를 받는 경로가 없다.

### `BattleManager`

- 모든 `Actor.OnDeath`를 `HandleActorDeath`에서 처리한다.
- `PlayerActor.Origin`을 통해 사망한 플레이어의 `CharacterSO`를 알 수 있다.
- 현재는 사망 시 승패만 판정하고 스포닝 재정규화 신호는 발행하지 않는다.

## 4. 설계

### 4.1 데이터 경계

`PuzzleFactory`에는 평면 버블 목록 대신 다음 두 종류의 후보를 주입한다.

- 생존 캐릭터별 스킬 후보 그룹
- 공용 특수 버블 후보 그룹

팩토리는 `Actor`, `Battlefield`, `GameManager`를 알지 않는다. 전달받은 후보와 가중치만으로 결과를 뽑는 순수 클래스 상태를 유지한다.

캐릭터별 스킬 그룹의 생성과 생존 여부 반영은 캐릭터-스킬 매핑을 이미 소유한 `PuzzleManager`가 담당한다. 동일한 소유 관계를 `PuzzleFactory`에서 다시 계산하지 않는다.

### 4.2 1단계 추첨

공용 그룹의 지분은 항상 10으로 고정한다. 나머지 90을 생존 캐릭터 수로 균등 분배한다.

| 생존 캐릭터 | 캐릭터별 지분 | 공용 지분 |
|---:|---:|---:|
| 3 | 30 | 10 |
| 2 | 45 | 10 |

MVP의 패배 조건상 생존 1인 상태에서는 전투 종료가 예약된다. 정상 플레이에서는 추가 스왑이 없어야 하지만, 팩토리는 잘못된 호출에도 예외를 내지 않도록 남은 캐릭터 1인에게 90, 공용에 10을 배정하는 방어 동작을 둔다.

생존 캐릭터가 없으면 공용 후보만 사용한다. 공용 후보도 없으면 기존처럼 경고 후 주입되지 않은 빈 `Bubble`을 반환한다.

### 4.3 2단계 추첨

캐릭터 그룹이 선택되면 해당 캐릭터의 유효한 스킬만 대상으로 `spawnWeight` 가중 추첨을 수행한다.

- `null` 후보는 제외한다.
- `spawnWeight <= 0`은 추첨 지분이 없는 것으로 처리한다.
- 그룹의 양수 가중치 합이 0이면 조용히 특정 스킬을 뽑지 않고 구성 오류 경고를 남긴다.
- 가중치 누적 비교와 난수 범위 계산은 한 함수에서만 수행한다.

GDD는 공용 특수 버블 `T_O` 하나를 전제로 한다. 현재 필드가 목록인 것은 인스펙터 배선을 위한 형태로 보고, 이번 작업에서는 유효한 공용 후보가 정확히 하나인지 검증한다. 여러 공용 버블 사이의 추가 확률 규칙은 임의로 만들지 않는다.

### 4.4 사망 신호 경로

신호는 아래 한 방향으로 흐른다.

```text
Actor.OnDeath
  → BattleManager.HandleActorDeath
  → GameManager.OnCharacterDied(CharacterSO)
  → PuzzleManager.HandleCharacterDied(CharacterSO)
  → PuzzleFactory 후보 구성 갱신
```

- `BattleManager`는 죽은 액터가 `PlayerActor`이고 `Origin`이 유효할 때만 캐릭터 사망을 알린다.
- `GameManager`는 이벤트를 중계할 뿐 생존 명단이나 확률을 계산하지 않는다.
- `PuzzleManager`는 사망한 `CharacterSO`를 생존 후보에서 한 번만 제외한다.
- 중복 사망 통지가 오더라도 두 번 제거하거나 경고를 반복하지 않도록 멱등적으로 처리한다.
- `PuzzleManager.OnDestroy`에서 반드시 구독을 해제한다.

### 4.5 적용 시점과 영수증 보존

현재 조작의 매치·중력·리필은 `PuzzleModel.Swap()`이 `MoveReceipt`로 먼저 확정한다. 전투 스킬 실행과 사망은 퍼즐 연출 완료 후 `GameActionState`에서 발생한다.

따라서 사망 신호를 받은 즉시 팩토리 후보를 갱신해도 이미 확정된 현재 영수증은 바뀌지 않으며, 갱신된 후보는 다음 스왑에서 요청되는 새 버블부터 사용된다. 기존 `MoveReceipt`나 보드 데이터를 다시 계산하거나 교체하지 않는다.

## 5. 구현 순서

### 1단계 — 변경 전 회귀 기준 확인

Unity 에디터에서 다음 두 항목을 먼저 확인한다.

- 사망 캐릭터의 기존 버블을 매치해도 전투 로그에 해당 스킬이 나오지 않는다.
- 패배 후 보드 입력과 힌트가 차단된다.

실패한다면 작업 `[6]`과 섞지 않고 기존 결함으로 먼저 보고한다.

### 2단계 — `PuzzleFactory` 추첨 모델 교체

- 평면 후보 필드를 캐릭터별 그룹과 공용 후보 구조로 교체한다.
- 1단계 그룹 추첨과 2단계 `spawnWeight` 추첨을 분리한다.
- 유효 후보, 가중치 합, 공용 후보 수에 대한 구성 검사를 추가한다.
- `PackBubble`은 최종 선택된 `BubbleSO`를 기존 `Bubble.Inject` 경로로 주입한다.

### 3단계 — `PuzzleManager` 후보 구성 변경

- `BuildSpawnTable()`을 캐릭터별 스킬 그룹을 만드는 단일 함수로 교체한다.
- 초기화 시 덱의 모든 유효 캐릭터를 생존 집합으로 등록한다.
- 공용 후보와 생존 캐릭터 후보를 팩토리에 주입한다.
- 기존 `skillOwners`를 색 판정과 후보 그룹 구성의 단일 소유 관계로 계속 사용한다.

### 4단계 — 사망 이벤트 중계

- `GameManager`에 `CharacterSO` 사망 이벤트와 발행 메서드를 추가한다.
- `BattleManager.HandleActorDeath`에서 플레이어 사망을 중계한다.
- `PuzzleManager`가 이벤트를 구독하고 생존 집합 및 팩토리 후보를 갱신한다.
- 승패 예약 로직의 기존 순서와 의미는 변경하지 않는다.

### 5단계 — 정적 점검

- `PuzzleManager`에 `Actor`/`Battlefield` 참조가 생기지 않았는지 검색한다.
- `BattleManager`가 `PuzzleManager`를 직접 참조하지 않는지 확인한다.
- 사망 이벤트 구독과 해제가 대칭인지 확인한다.
- 기존 평면 후보 API 호출이 남지 않았는지 검색한다.
- 정상 흐름을 계속 출력하는 임시 진단 로그는 검증 후 제거한다.

### 6단계 — Unity 에디터 검증

- 컴파일 오류와 직렬화 경고가 없는지 확인한다.
- 초기 보드 생성, 스왑, 연쇄, 중력, 리필, 데드락 셔플이 정상인지 확인한다.
- 충분한 표본을 임시로 수집해 3인 생존 시 `3:3:3:1`에 수렴하는지 확인한다.
- 캐릭터별 세 스킬이 `spawnWeight` 비율에 수렴하는지 확인한다.
- 아군 1인 사망 후 새 생성분이 `4.5:4.5:1`에 수렴하고 사망 캐릭터 스킬이 0건인지 확인한다.
- 사망이 발생한 현재 조작의 영수증과 화면 연출이 중간에 바뀌지 않는지 확인한다.
- 보드에 남은 사망 캐릭터 버블이 계속 매치·파괴되고 스킬만 무효인지 확인한다.
- 패배 후 입력 차단과 승패 전이에 회귀가 없는지 확인한다.

확률 표본 수집용 코드나 로그를 넣었다면 결과 확인 후 제거한다.

## 6. 완료 기준

- GDD §3.2의 두 단계 추첨이 코드 구조로 구분된다.
- 1단계 지분과 2단계 `spawnWeight`가 서로 섞이지 않는다.
- 사망 정보가 `BattleManager → GameManager → PuzzleManager` 경로로만 전달된다.
- 사망 캐릭터는 다음 스왑의 신규 생성 후보에서 제외된다.
- 현재 조작의 `MoveReceipt`와 기존 보드 버블은 수정되지 않는다.
- 정상 플레이와 경계 입력에서 인덱스 오류나 빈 후보 예외가 발생하지 않는다.
- 임시 조사 로그가 제거되어 있다.
- Unity 에디터 컴파일 및 플레이 검증 결과가 기록되어 있다.
